Error handling with fetch()

A failed server response is not the same as a broken network.

The big gotcha in fetch() is this: fetch resolves even when the server responds with 404 or 500. You must check response.ok.

async function loadUser() {
  try {
    const response = await fetch('https://example.com/missing-page');
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error('Something went wrong:', error.message);
  } finally {
    console.log('This always runs');
  }
}
Quick rule: no internet → fetch rejects automatically. 404/500 → fetch resolves, so check response.ok yourself.

Common pattern

  • try: code that may fail
  • catch: show the error to the user
  • finally: hide loading spinners or reset buttons
